## 🐛 Bug Description
In the **View Student Records** page (`ViewStudentRecords.jsx`), clicking the **"EXPORT PDF"** button currently opens a new popup browser window and invokes `window.print()`. This opens the browser's physical print dialogue rather than downloading a formatted `.pdf` document directly to the teacher's Downloads folder.

## 🎯 Proposed Solution
1. Connect the **"EXPORT PDF"** button in `ViewStudentRecords.jsx` to the existing backend endpoint:
   `GET /api/tracking/records/{studentId}/export/`
2. Fetch the binary PDF stream generated by `BinaryReportRenderEngine` and trigger a direct client-side file download (`StudentRecord_<StudentName>.pdf`) using `URL.createObjectURL(blob)`.
3. Provide visual loading feedback ("Exporting PDF...") and accessible error alerts if the download fails.

## 📋 Requirements
- [ ] In `neuropath-frontend/src/api/client.js`, add `exportStudentRecordPDF: (studentId) => ...` or handle direct blob download with authorization headers.
- [ ] In `ViewStudentRecords.jsx`, replace `window.print()` popup logic with direct blob download.
- [ ] Clean up object URLs via `URL.revokeObjectURL(url)` to prevent memory leaks.
- [ ] Add unit test in `ViewStudentRecords.test.jsx` verifying that clicking "EXPORT PDF" triggers the file download.

## 🧪 Acceptance Criteria
- [ ] Clicking "EXPORT PDF" directly downloads `StudentRecord_<Name>.pdf` without opening the browser print dialogue.
- [ ] The generated PDF contains the complete student profile, IEP baseline data, Section B difficulties & accommodations, and Section C learner goals.
- [ ] All frontend unit tests pass (100% green).
